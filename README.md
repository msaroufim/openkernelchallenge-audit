# Open Kernel Challenge / KernelBot overlap

- **Matching seed-mixing formula:** all 60 benchmark seeds from two live runs exactly fit [reference-kernels’ Cantor pairing](https://github.com/gpu-mode/reference-kernels/blob/f3295bb6bd559bae4659d2d8fc45edb1394251b1/problems/nvidia/eval.py#L50), with OKC additionally applying modulo `2^63 − 1`. The formula is present in GPU MODE’s [July 17, 2025 source](https://github.com/gpu-mode/reference-kernels/blob/be20768224c7e36bba0b95ede255fe7755534931/problems/pmpp_v2/eval.py#L47). [Evidence](probes/seed-comparison.json) · [Reproduce](probes/check_seed_formula.py).
- **Same validation-failure exit code:** Three ordinary failing OKC submissions returned `112`, matching [KernelBot’s `VALIDATE_FAIL = 112`](https://github.com/gpu-mode/kernelbot/blob/ec4669669d368c395675565831f98b509db2b0b3/src/libkernelbot/consts.py#L76) and [reference-kernels](https://github.com/gpu-mode/reference-kernels/blob/f3295bb6bd559bae4659d2d8fc45edb1394251b1/problems/nvidia/eval.py#L199). [Live results](probes/ordinary-errors.json).
- **Same six benchmark statistics:** `runs`, `mean`, `std`, `err`, `best`, `worst`; OKC adds `_ns` to timing fields. Its returned numbers match sample standard deviation and `err = std / sqrt(runs)`. The surrounding JSON format differs. [Comparison](probes/code-output-comparison.json).
- **Same mode names:** `test`, `benchmark`, `leaderboard`, `profile` appear in OKC's binary and [KernelBot](https://github.com/gpu-mode/kernelbot/blob/9c242e5ef573c88047427989aa7d9b72ffb29232/src/libkernelbot/consts.py).
- **Same submission filename:** both use `submission.py`. [OKC](https://openkernelchallenge.dev/llms.txt) · [Popcorn](https://github.com/gpu-mode/popcorn-cli/blob/036b3ead604f1e9f404cbee5cf0e48377ef0766f/src/cmd/setup.rs#L285).
- **Same reference-function names:** `generate_input`, `ref_kernel`, `check_implementation` in [OKC](https://openkernelchallenge.dev/api/v1/problems/muse_moe_w4a16) and [GPU MODE](https://github.com/gpu-mode/reference-kernels/blob/f3295bb6bd559bae4659d2d8fc45edb1394251b1/problems/nvidia/nvfp4_gemv/reference.py).
- **Same problem-file layout:** OKC’s live evaluator reports `problems/<problem>/task.yml` and `reference.py`, matching [reference-kernels](https://github.com/gpu-mode/reference-kernels/tree/f3295bb6bd559bae4659d2d8fc45edb1394251b1/problems/nvidia/nvfp4_gemv). [Evaluator manifest](probes/results.json).
- **Similar submission directives:** OKC's `# okc: problem=...` and [Popcorn's](https://github.com/gpu-mode/popcorn-cli/blob/036b3ead604f1e9f404cbee5cf0e48377ef0766f/src/utils/mod.rs#L20) `#!POPCORN leaderboard ...` select the problem from a source comment.
- **Single-file CUDA submissions:** both document submitting one Python file and embedding native CUDA through PyTorch's `load_inline`/nvcc. [OKC](https://openkernelchallenge.dev/llms.txt) · [Popcorn](https://github.com/gpu-mode/popcorn-cli/blob/036b3ead604f1e9f404cbee5cf0e48377ef0766f/README.md#L279).
- **Geometric-mean aggregation:** OKC aggregates load speedups; reference-kernels supports geometric means of benchmark times. [OKC's `task_md`](https://openkernelchallenge.dev/api/v1/problems/muse_moe_w4a16) · [reference-kernels](https://github.com/gpu-mode/reference-kernels/blob/f3295bb6bd559bae4659d2d8fc45edb1394251b1/problems/nvidia/nvfp4_gemv/task.yml#L25).

- **No full-dataset release commitment:** the published rules require Apache 2.0 licensing of submissions but do not promise publication of the complete submission dataset after the contest. [Technical rules](https://openkernelchallenge.dev/llms.txt) · [Official terms, §13](https://openkernelchallenge.dev/terms.pdf#page=6).

- **Available-source comparison:** 23 OKC Python files (14 unique) versus 421 tokenizable GPU MODE files, now including pygpubench: no exact runs of 25 tokens or name-normalized runs of 40 tokens. The private server implementation remains unavailable. [Scope and results](probes/code-output-comparison.json).
